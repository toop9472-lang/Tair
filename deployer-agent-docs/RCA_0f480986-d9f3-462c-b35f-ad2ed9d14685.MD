## Root cause
`backend/requirements.txt` line 76 pins `lintiq==0.1.3`. This package does not exist on any configured index:
- public PyPI (`https://pypi.org/simple`)
- the private emergentintegrations CDN (`https://d33sy5i8bnduwe.cloudfront.net/simple/`)

Every other requirement in the file resolved ("Requirement already satisfied") — `lintiq` is the sole failing line. It is an orphan/hallucinated dependency: **no backend `.py` file imports `lintiq`** (verified with `grep -rn -i lintiq backend --include=*.py` → no matches). The previous run (6edc434b) which is currently live did not have this line; it was introduced into requirements.txt since.

## Fix (verified in eph sandbox)
Delete line 76 of `backend/requirements.txt`:
```
lintiq==0.1.3
```
Verification performed in the eph pod against the run's pulled source:
- `pip index versions lintiq` → `No matching distribution found for lintiq` (confirms it is unresolvable everywhere).
- `grep -rn -i lintiq backend --include=*.py` → no results (confirms it is unused, safe to remove).
- Removing the line yields a clean requirements file with zero `lintiq` references.

(Note: a full from-scratch `pip install -r` of the entire file inside the sandbox hit the pod resource ceiling — exit 137 — which is a sandbox artifact, not a dependency error. In the real build all other packages are pre-satisfied by the base image, as the failing build log shows.)
